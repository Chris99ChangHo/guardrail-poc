# guardrail-poc — AI 에이전트 "통제된 자율성" PoC

기술유출에 민감한 기업 환경에서 AI 에이전트와 바이브 코딩을 안전하게 쓰기 위한 **행동 통제 계층**의 개념 증명(Proof of Concept)입니다.
에이전트가 명령어나 코드를 실행하기 **직전에** 위험도를 판정해 자율 / 승인 / 차단으로 나누고, 결과는 **출력 직전에** 개인정보·키 패턴을 마스킹하며, 모든 판정을 감사 로그로 남깁니다.

> 이 프로젝트는 "기술유출에 민감한 기업(예: 반도체)이 AI를 도입한다"는 **가정 시나리오**를 바탕으로 한 PoC입니다.
> 배경 기사 인용 시 기사명·날짜·링크를 직접 기입하세요: `[기사명 / 날짜 / URL]`

---

## 1. 문제 정의

| 층 | 질문 | 수단 | 이 PoC |
|---|---|---|---|
| 1. 데이터 위치·계약 | 데이터가 어디에 저장되고 학습에 쓰이나? | 국내 저장, 기업용 계약, 전용 배포 | 범위 밖 |
| 2. 접근 통제 | 누가 어떤 데이터를 보나? | 권한 관리, 문서 등급 | 범위 밖 (확장 후보) |
| 3. 에이전트 행동 통제 | AI가 내부에서 무엇을 실행하나? | 실행 전 판정 | **구현** |
| 4. 유출 방지·감사 | 나가는 정보는 걸러지고 기록되나? | 마스킹, 감사 로그 | **구현** |

데이터를 국내에 두고 기업용 모델을 들여와도, 에이전트가 내부 파일을 마음대로 열거나 외부로 보내는 위험은 남습니다. 이 PoC는 3, 4층의 공백을 다룹니다.

## 2. 핵심 개념: 세 가지 판정

| 판정 | 의미 | 예 |
|---|---|---|
| 🟢 allow | 자율 실행 | `ls`, `cat notes.txt`, 정상 데이터 분석 코드 |
| 🟡 ask | 사람 승인 후 실행 | `rm`, `pip install`, `curl`, 경로를 정적으로 알 수 없는 `open(name)` |
| 🔴 block | 즉시 차단 | `cat ../.env`, `rm -rf`, `import os`, `import requests` |

원칙: **알려진 위험은 차단, 알 수 없는 것은 승인, 명확히 안전한 것만 자율.** 미등록 명령어는 기본적으로 승인을 요구합니다.

## 3. 아키텍처

```
[개발자: CLI 래퍼 guard.py]  ─┐
                              ├─▶ [Guardrail Core: core.py]
[비개발자: 웹 UI app.py]     ─┘      · policy.yaml (규칙)
                                     · 경로 검사 / 명령어 검사 / 코드 AST 검사
                                     · 판정: allow | ask | block
                                              │
                           ┌──────────────────┼──────────────────┐
                           ▼                  ▼                  ▼
                       실행(격리 -I)     사용자 승인 대기      차단(미실행)
                           │                                      │
                      출력 마스킹(mask)                           │
                           └────────────▶ audit.log (JSON Lines) ◀┘
```

개발자용 CLI와 비개발자용 웹 UI는 **같은 코어와 같은 policy.yaml**을 공유합니다. 입구만 둘이고 규칙은 하나입니다.

## 4. 파일 구성

| 파일 | 역할 |
|---|---|
| `policy.yaml` | 규칙 정의. 정책을 바꿀 때는 이 파일만 수정 |
| `core.py` | `Guard` 클래스(판정 엔진)와 `mask()` |
| `guard.py` | 개발자용 CLI 래퍼 |
| `app.py` | 비개발자용 Streamlit 웹 UI (공정 데이터 분석 엔지니어 페르소나) |
| `demo_attacks.py` | 공격 시나리오 + 마스킹 테스트. 기대 판정과 다르면 실패 |
| `workspace/` | 에이전트가 접근 가능한 유일한 폴더 (샘플 데이터 포함) |
| `HANDOFF.md` | 로컬 에이전트에게 작업을 넘길 때 쓰는 핸드오프 문서 |
| `audit.log` | 실행 중 생성되는 감사 로그 (`demo_audit.log`는 데모용) |

## 5. 설치와 실행

```bash
pip install -r requirements.txt        # pyyaml, streamlit, pandas
python demo_attacks.py                 # 시나리오 검증 + 마스킹 데모
pytest                                 # 우회 사례 회귀 테스트 (알려진 한계는 xfail)
python guard.py run "cat notes.txt"    # CLI: 허용
python guard.py run "cat ../.env"      # CLI: 차단
python guard.py log 10                 # 최근 감사 로그 10건
streamlit run app.py                   # 웹 UI
```

Python 3.9 이상이 필요합니다 (`Path.is_relative_to` 사용).

## 6. 사용 가이드

### 6.1 CLI (개발자용)
- `guard run "<명령어>"`: 명령어를 판정한 뒤 🟢 실행, 🟡 `[y/N]` 승인 질문, 🔴 차단합니다.
- 실행은 `shell=False`로 하므로 `;`, `|`, `&&` 같은 체이닝은 해석되지 않고 단순 인자로 취급됩니다.
- 종료 코드: 차단 2, 사용자 거부 3, 명령어 없음 127.
- 출력은 항상 마스킹을 거칩니다.

### 6.2 웹 UI (비개발자용)
1. "요청 선택"에서 시나리오를 고르면 "AI가 생성했다고 가정한 코드"가 채워집니다 (LLM은 연동하지 않았습니다).
2. 코드는 수정해서 직접 시험할 수 있습니다.
3. **검사 후 실행**을 누르면 결과가 세 가지로 나뉩니다.
   - 통과: 코드가 실행되고 결과(필요 시 차트)가 표시됩니다. 개인정보 패턴은 가려집니다.
   - 승인 필요: 이유와 함께 **승인하고 실행** 버튼이 나타납니다.
   - 차단: 실행 전에 막히고 이유가 평이한 말로 표시됩니다.
4. 하단 "감사 로그"에서 최근 10건의 판정 기록을 볼 수 있습니다.

### 6.3 시연용 캡처 조합
1. 정상: "공정 수율 월별 추이" (차트)
2. 마스킹: "라인별 담당자 목록" (`***@***`)
3. 차단: "시스템 환경변수 출력"의 붉은 박스 + 감사 로그를 펼친 화면
4. CLI: `python demo_attacks.py` 실행 결과 표

## 7. 판정 로직 상세

### 7.1 경로 검사 (`_path`)
- `~`를 펼치고, 상대 경로는 `workspace/` 기준으로 해석한 뒤 `resolve()`로 `../` 등을 정규화합니다.
- 경로의 어느 구성요소든 `blocked_names`(`.env`, `.ssh`, `.aws`, `.gnupg`)이거나 `.env`로 시작하면 차단합니다.
- 정규화된 경로가 `workspace/` 밖이면 차단합니다.

### 7.2 명령어 검사 (`_cmd`)
1. 소문자로 바꿔 `blocked_commands` 문자열 포함 여부 검사 → 포함 시 차단
2. `shlex.split`으로 쪼개고, 경로처럼 생긴 인자(`/`, `\`, `.`·`~` 시작, 금지 이름)를 경로 검사 → 하나라도 차단이면 차단
3. `--file=../.env`처럼 `=` 뒤에 경로가 붙은 옵션도 값을 꺼내 검사
4. 명령어(또는 앞 두 단어)가 `ask_commands`면 승인, `auto_commands`면 허용, 둘 다 아니면 승인

### 7.3 코드 검사 (`_code`)
`ast`로 구문 트리를 순회하며 다음을 찾습니다.
- **허용 목록 밖** 모듈 `import`는 전부 차단 (허용: pandas, numpy, math, statistics, json, csv, datetime, re, collections, itertools)
- 금지 함수 호출 (`eval`, `exec`, `compile`, `__import__`, `getattr`, `setattr`, `globals`, `locals`)
- 금지 속성 접근 (`environ`, `__globals__`, `__builtins__`, `__subclasses__`)
- `open`, `read_csv`, `np.load` 등 파일 읽기 함수의 첫 인자와 `file=`/`path=` 등 키워드 인자: 문자열 리터럴이면 경로 검사, 리터럴이 아니면 승인(정적으로 알 수 없음)

### 7.4 코드 실행 (`run_code`)
검사 통과 후 `python -I -c <코드>`를 `workspace/`를 작업 폴더로, 10초 제한으로 실행하고, stdout/stderr 모두 마스킹해 반환합니다. **진짜 샌드박스가 아닙니다** (9장 참고).

### 7.5 마스킹 (`mask`)
주민등록번호, 휴대폰 번호, 이메일, API 키 패턴(`sk-...`, `AKIA...`)을 정규식으로 치환합니다. 현재는 **출력**에만 적용됩니다.

### 7.6 감사 로그
`audit.log`에 한 줄에 JSON 하나씩 기록됩니다.
```json
{"ts": "2026-11-14T12:00:00", "kind": "command", "target": "cat ../.env", "verdict": "block", "reason": "민감 경로 접근 시도: ../.env"}
```
- `kind`: `path` | `command` | `code`
- `verdict`: `allow` | `ask` | `block`, 사용자 응답은 `approved` | `denied`
- `target`은 200자까지만 기록합니다.

## 8. 정책 커스터마이징 (`policy.yaml`)

| 키 | 설명 |
|---|---|
| `workspace` | 접근 허용 루트 폴더 |
| `blocked_names` | 경로에 들어 있으면 차단할 이름 |
| `blocked_commands` | 명령어에 포함되면 차단할 문자열 |
| `ask_commands` / `auto_commands` | 승인 / 자율 명령어 |
| `allowed_modules`(허용 목록) / `blocked_calls` / `blocked_attrs` | 코드 검사 금지 목록 |
| `file_readers` | 첫 인자가 경로인 함수 이름 |

예: `ask_commands`에 `git push`를 이미 넣어 두었습니다. 사내 코드명 같은 민감 키워드를 다루려면 `mask()`의 패턴 목록(`core.py`)을 확장하세요.

## 9. 알려진 한계 (솔직하게)

직접 검증한 우회 사례와 조치 상태입니다.
- **`python`이 자율 허용되어 코드 검사를 통째로 건너뛰던 구멍 (수정됨)**: `python -c 'import os...'`가 allow였습니다. `python`을 `auto_commands`에서 제거해 기본 승인(ask)으로 처리합니다. 단 승인 후 실행되는 코드 자체는 CLI 경로에서 검사되지 않습니다.
- **키워드 인자·별칭 (수정됨)**: `open(file='../.env')`, `f = open; f('../.env')` → 키워드 인자 검사 추가, 금지 함수를 값으로 참조하면 차단.
- **단문 옵션에 붙은 경로 (수정됨)**: `cat -f../.env` → 옵션 값도 경로 검사. `rm  -rf`(공백 2개)·`rm -r -f` → 공백 정규화와 플래그 토큰 단위 판정으로 block.
- **차단 목록의 한계 (허용 목록으로 전환)**: `fileinput`, `numpy.load`, `platform.os.getenv('HOME')`이 통과했습니다. 모듈은 허용 목록 방식으로 바꾸고 `os`/`sys`/`builtins`/`getenv` 속성 접근도 차단합니다.
- **실행 환경 (보강)**: `run_code`는 최소 환경변수로 실행하고 `TimeoutExpired`를 처리합니다.
- **여전히 남은 한계 (직접 검증된 우회 사례)**:
  - **허용 모듈의 파일 쓰기 함수(`to_csv`, `save`)**: `pd.DataFrame().to_csv('../leak.csv')`, `np.save('../leak.npy', ...)` 등 쓰기 전용 함수는 `file_readers` 목록에 없어 workspace 밖 쓰기가 allow로 통과합니다 (쓰기 권한 분리 모델 부재).
  - **허용 모듈의 네트워크 I/O(`read_csv` URL)**: `pd.read_csv('http://example.com/x.csv')`처럼 URL 형태 인자를 전달할 경우 내부 네트워크 다운로드가 차단되지 않습니다.
  - **문자열 조합 경로 / 인코딩 마스킹 (xfail 테스트)**: 문자열 덧셈으로 조립한 경로는 정적 분석 불가로 ask 처리되며, base64 등 인코딩된 출력은 정규식 마스킹을 우회합니다.

그 밖의 구조적 한계:
- 정적 분석은 난독화되었거나 동적으로 생성되는 코드를 완전히 막을 수 없습니다. 차단 목록 방식이라 목록에 없는 경로는 놓칩니다.
- `run_code`의 `-I`는 격리 모드일 뿐 샌드박스가 아니며, 네트워크·파일 시스템을 OS 수준에서 막지 않습니다.
- 에이전트가 이 가드를 **우회하는 다른 경로**(자체 내장 도구 등)를 쓰면 막지 못합니다. MCP는 도구를 추가할 뿐 기존 도구를 없애지 않습니다.
- 에이전트가 설정 파일을 고쳐 훅을 끄는 것까지 막으려면 격리가 필요합니다.

결론: 검사 로직만으로는 부족하고, **우회할 수 없는 강제 지점**(실행 직전 훅, OS/컨테이너 격리, 읽기 전용 마운트, 네트워크 차단)과 함께 써야 실효가 있습니다.

## 10. 고도화 로드맵

1. 입력(프롬프트) 마스킹: 모델에 보내기 전에 민감 정보를 거르기
2. 폴더별 읽기/쓰기 권한 모델과 대량 출력 승인
3. 허용 목록 방식 병행: 필요한 모듈만 허용 (`fileinput`, `zipfile` 등 누락 경로 대응)
4. 에이전트 훅 연동: 실행 직전에 `check_command` 호출
5. 컨테이너 격리, 네트워크 차단 등 인프라 계층과 결합
6. 판정 로그를 대시보드로 시각화, 정책 버전 관리

## 11. 포트폴리오에 담는 법 (1~2페이지)

1. **문제 정의**: 위 1장의 표와 한 문장 ("국내 저장으로 위험이 줄어도 에이전트의 행동은 별도 통제가 필요")
2. **아키텍처**: 3장 도식 1장
3. **결과**: 정상 vs 공격 캡처, `demo_attacks.py` 전체 통과 결과
4. **한계와 방향**: 9장의 우회 사례와 10장의 로드맵. 한계를 직접 검증해서 밝혔다는 점이 신뢰를 줍니다.
